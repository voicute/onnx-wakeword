# Wake + Command demo for ESP32-S3-HMI-DevKit (own KWS models, MultiNet removed)

English | [中文](README_CN.md)

This is a complete board-specific application using the Voicute SDK. It runs
**two of our own KWS models** (Causal DS-TCN) on one board and replaces the
Espressif MultiNet command model entirely:

- **Wake model** — `hallo_lumo.tflite` ("Hallo Lumo", single MultiProto head, K=5)
- **Command model** — `licht_multi.tflite` ("Licht rot/blau/grün/weiß", multi-head, N=4 × K=3)

Both models are mel_time=150 exports (1.532 s window / 24512 samples @ 16 kHz,
32 mels). Verified on board: 20+ wakes (prob 0.73–1.000) in noisy (rms 150–190)
and quiet (rms 24–36) rooms, all four colour commands hit with zero confusion;
mel ≈ 47 ms + invoke ≈ 76 ms ≈ 121 ms per 160 ms frame (real time).

## Supported hardware

Tested on **ESP32-S3-HMI-DevKit**: ESP32-S3 at 240 MHz, 8 MB octal PSRAM, 16 MB
flash, four MEMS microphones through ES7210, ES8311 audio output, a WS2812 LED
chain, and 16 kHz audio. The verified framework is **ESP-IDF 6.0.1**.

Porting to other boards requires changes to `main/bsp_board.c`, GPIO
assignments, codec configuration, and possibly partition/PSRAM settings.

## Architecture: one inference path, two models, time-divided

The tflite files contain **only the backbone**; the MultiProto heads are float
C arrays compiled into the firmware (`main/head.h`). The two models share the
same audio → mel → invoke pipeline; a state machine gates which one is active:

```text
IDLE    → wake model only   (hallo_lumo, rolling window)
COMMAND → cmd model only    (licht_multi, same window), 6 s timeout → IDLE
```

Gating is per-model `recognizer_set_active()` — a disabled model skips Invoke
entirely, so COMMAND mode costs nothing extra. Key pieces in `main/main.cpp`:

| Piece | Role |
|---|---|
| `resolve_model_indices()` | Maps roles to registry indices by **filename stem** (`hallo_lumo` / `licht_multi`) — SPIFFS readdir order is not guaranteed, never hard-code indices |
| `dispatch_postprocess()` | postprocess callback with `model_idx`: cmd model → `kws_postprocess_cmd()` + **caller-side argmax** (it returns the head *count*, not the winner); wake model → `kws_postprocess_wake()` |
| `on_wake` / `on_cmd` / `leave_cmd` | State transitions. Every switch does `recognizer_set_active()` **and** `recognizer_reset_smooth()` — a prob peak left in the smoothing buffer would re-fire the other model right after the switch |
| `led_show()` | This board's WS2812 chain renders R/G swapped relative to `led_strip_set_pixel`'s argument order; the swap is done once here so callers pass logical RGB |

Detector config: `threshold=0.70f` for both models, L1–L5 gates disabled
(threshold-only decision; validated on board). The export package recommends
0.5 per word — 0.70 worked for every command, but lower it if a word misses.

## Model directory: what goes where

| File | Content | Replaces with |
|---|---|---|
| `spiffs_content/hallo_lumo.tflite` | wake backbone (int8, ~67 KB) | your wake model's `*.tflite` |
| `spiffs_content/licht_multi.tflite` | cmd backbone (int8, ~67 KB) | your cmd model's `*.tflite` |
| `main/head.h` | **merged** MultiProto heads (generated — do not edit by hand) | regenerated by `_merge_heads.py` |

The tflite filename stem (without extension) is the model identifier the
firmware resolves roles from. SPIFFS partition is 1 MB; both tflites are
packed into the image automatically at build time.

**A `*.tflite` and `main/head.h` are a matched pair and must be replaced
together** — the head weights must come from the same training run as the
backbone, or probabilities are meaningless.

## How the heads are merged (`main/_merge_heads.py`)

Two models cannot each ship their own `head.h`: the export zips all define the
same symbols (`KWS_FC_W`, `KWS_PROTO_NORM`, `kws_postprocess_multi`, …), which
would clash at link time. The generator script merges the two shipped `head.h`
files into one header with prefixed symbols:

- wake model → `KWS_WAKE_*` (`KWS_WAKE_FC_B/W`, `KWS_WAKE_PROTO_NORM`,
  `KWS_WAKE_ABS_TEMP`) + a hand-written `kws_postprocess_wake()`
  (single head: `sigmoid(b + Σ W[k]·cos/T)`)
- cmd model → `KWS_CMD_*` (`KWS_CMD_N`, `KWS_CMD_K`, weight arrays) +
  `kws_postprocess_multi` renamed to `kws_postprocess_cmd`
- common defines: `KWS_MEL_TIME 150`, `KWS_N_MELS 32`, `KWS_HEAD_D 256`,
  `KWS_WAKE_K`, `KWS_CMD_N`, `KWS_CMD_K`, `KWS_CMD_WORD_0..N`

To regenerate for new models:

1. Unzip both model export packages and locate each `head.h` (plus the
   `*.tflite` from the tflite package).
2. Edit the three hardcoded paths at the top of `main/_merge_heads.py`
   (`HALLO`, `LICHT` = the two head.h inputs, `OUT` = `main/head.h`).
3. Run it (any Python 3, stdlib only): `python main/_merge_heads.py`
4. Drop the two tflite files into `spiffs_content/` **using the stems the
   firmware matches on** (or update `resolve_model_indices()` to match yours).
5. Update `g_cmd_names[]` / the LED mapping in `on_cmd` for your command words.

**Constraint:** all merged models must share the same mel configuration —
the merged header carries a single set of mel defines (`KWS_MEL_TIME`,
`KWS_N_MELS`). Two models with different `mel_time` cannot be merged this way;
they would need separate headers and separate input windows.

Sanity check before flashing: the generated header is plain C — compile it on
the host (`gcc -c` with `-lm`) and call both postprocess functions on a
garbage int8 buffer; expect near-zero wake prob and N per-head probs out.

## Build and flash

From this directory in an ESP-IDF 6.0.x shell:

```bash
idf.py set-target esp32s3
python patch_led_strip.py
idf.py build
idf.py -p COM6 flash monitor
```

On Windows, `build.bat` performs target selection, the compatibility patch,
and build. Update the COM port in `flash.bat` before flashing.

## Serial console notes (Windows)

- ESP_LOG lines contain `→` (U+2192); a cp1252 Python capture script crashes
  printing them. Use `PYTHONIOENCODING=utf-8` and
  `sys.stdout.reconfigure(errors="replace")` (see `_serial_capture.py`).
- Reopening the USB-Serial-JTAG port asserts DTR and **hard-resets the board**
  — don't reconnect on exceptions unless a reset is intended.
